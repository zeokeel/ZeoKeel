# 00 · 设计原则（v3.2：服务端弱管控）

> **v3.2 总基调**：企业版**不是**"强管控终端"。服务端只管**认证、钱包/网关、商店内容、审计、管理台**；
> 客户端能力**完整下发**；工具默认全开、网络默认全开、不做企业审批。
> 本文件是设计原则；与其它文档冲突时按 `AGENTS.md` §10 的权威顺序
> （用户当前指令 > AGENTS.md > 00/15 > 19–24 > PLAN > 其它 docs > research）。
>
> 个人版更自由（无服务端、无登录、无应用中心）；OEM 继承企业版并可换品牌/商店内容。

## 1. 一句话

**服务端管"身份、钱、商店、记录"，不管"员工怎么用客户端"。**
企业的可控性来自：谁能登录、能花多少钱、能装到哪些企业内容、出了事能查到；而不是限制员工的每一次点击。

## 2. 十条原则

| # | 原则 | 含义 | 落到哪里 |
| --- | --- | --- | --- |
| P1 | **服务端弱管控** | 只做认证/会话、钱包与网关计费、商店（技能/连接器/应用分发）、审计、管理台；不干预客户端工具与操作 | 服务端包范围（07） |
| P2 | **客户端能力完整** | 企业版员工拥有客户端全部能力：工具全开、网络全开、本地审批可配；服务端不下发工具白名单/网络策略/审批策略 | 客户端包集合（01/05） |
| P3 | **商店是唯一内容管控点** | 企业技能/连接器/应用由服务端分发、版本化、可下架；员工上传需管理员审核；删除即同步失效 | 07 §5–§7 |
| P4 | **按钮语义明确** | 每个按钮一个明确动作：有输入约束、有确定结果、无隐藏副作用；不允许"点了不知道会发生什么" | UI 规范、API 契约 |
| P5 | **单一真源与上限** | 限额/超时/重试/并发/大小/配额一处定义、生成到前后端；这是工程一致性，不是限制员工 | `limits` + 生成物 |
| P6 | **失败可预期** | 错误码字典、超时、幂等、重试退避、回滚；不出现"未知状态/无限等待" | 错误模型、状态机 |
| P7 | **变更可控** | 配置标注 hot/restart；版本/渠道/OEM 在构建期固定，运行期不可换；支持回滚 | 配置、发布流程 |
| P8 | **无隐藏入口** | 企业版不含调试/开发者菜单/未公开开关；所有功能在 UI 与文档中可见 | edition 裁剪 |
| P9 | **一切可审计** | 登录、AI 调用、充值/扣费、内容安装/删除、管理操作都有记录，可按人/时间/对象查 | 审计表、事件 |
| P10 | **可验证** | 每条规则对应 CI 测试或门禁，不靠"人记得" | 测试矩阵、`zk` 校验 |

## 3. 明确"不再是原则"（v3 强管控内容已废弃）

| 已废弃 | 原因 |
| --- | --- |
| 默认拒绝（deny-by-default） | 需求方决定弱管控；能力全部下发 |
| 工具白名单 / 按工具限制 | 不做；默认全部允许 |
| 网络域名白名单 / 默认关闭 | 不限制；默认开启、允许所有地址 |
| 企业审批（服务端下发审批策略） | 不做"企业审批那套"；员工有全部能力 |
| 员工设置页收窄（只读策略） | 客户端能力完整；仅保留"企业不可改 provider"这一条（AI 走网关） |
| 部门/用户组 | 已删除该功能（企业实践不再需要） |

**唯一保留的"服务端限制"**：
1. 企业版 AI **只能走服务端网关**（员工不能自配 provider / 填上游 key）——这是计费与密钥安全的硬约束；
2. 企业内容（技能/连接器/应用）**只能从企业商店安装**——这是商店与版本可控的硬约束；
3. 员工被禁用后**立即失效**——认证硬约束。

## 4. 各角色能看到/能做什么

| 角色 | 客户端 | 管理台 |
| --- | --- | --- |
| 员工 | 完整客户端能力（工具/网络/本地审批/本地技能/MCP） | 无 |
| 超管 | 同员工 + 管理台全部写权限 | 全部 |
| 审计员 | 同员工 | **只读**：审计、用量、登录事件、内容变更记录；不能改任何配置 |

## 5. 安全边界（弱管控下必须写清楚）

- 服务端**不为员工行为兜底**：工具执行、命令执行、网络访问、文件操作发生在员工机器上；
  安全责任由客户终端管理、网络边界与员工培训承担。
- 服务端的安全投入集中在：认证、令牌、网关密钥、商店内容审核（人工）、升级通道、审计完整性。
- 因此文档与销售材料**不得宣称**"企业版可以限制员工操作"；只能宣称"可管理身份、费用与企业内容"。
- 不做插件沙箱承诺；WASM 应用是唯一沙箱（且应用不可调 AI、无网络/文件）。

## 6. 个人版与 OEM

- **个人版**：纯客户端、无服务端、无登录、无应用中心；自配 provider、本地工具/技能/MCP 全自由。
- **OEM**：继承企业版的弱管控 + 可换品牌/文案/默认配置/商店内容；深度 OEM 可换实现包（同契约）。
- **参考仓库边界**：`zeokeel/channels`、`ZeoKeel-Harness`、`ZeoKeel-Next` 只作事实/设计参考，
  不得作为依赖、构建输入、索引仓或数据源；我们的索引仓必须自有命名。

## 7. 新增功能时的必答问题

1. 它属于企业版还是个人版？是否需要服务端？
2. 它是"商店内容"（需审核/分发）还是"客户端能力"（直接下发）？
3. 是否有服务端强制点（认证/计费/内容）？没有的话不要放服务端。
4. 失败长什么样？错误码是什么？能否重试/回滚？
5. 是否可审计？审计失败时业务是否 fail-closed？
6. 哪些是构建期固定（edition/渠道/OEM），哪些运行期可配？
7. 对应的 CI 测试/门禁是哪一条？
