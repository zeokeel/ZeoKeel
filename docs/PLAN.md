# PLAN · ZeoKeel 平台总规划（v3.2）

> **一切皆包的 Rust 企业级 Agent 平台。**
> 客户端 + 服务端 + 管理后台全部由可替换的包组成；构建期组合；内核 `zeokeel-cordis`；
> 模型层 `rig`；组织方式参考 DeepSeek Harness 与 ZeoKeel-Harness。
>
> v1 是单机客户端规划，v2 经对抗性评审修订；**v3 扩展为平台**（服务端、企业版/个人版、OEM 白标、
> Docker 交付、AI 网关与计费、技能中心、连接器、WASM 应用中心、管理台）。
>
> **优先级（v3.2）：客户端是产品主体。** 先做客户端壳/UI/agent/工具/本地体验；服务端只做配套的
> 认证、钱包/网关、商店与审计；**WASM 应用中心后置**。服务端七域文档是「需要时怎么做」，不是当前主线。
> 已拍板事项见 [`15-open-questions.md`](15-open-questions.md) 的"已定"清单，剩余细节见 `15` 与 `AGENTS.md` §12。

## 2. 一句话架构

```text
┌──────────────────────── 客户端（企业版 / 个人版）────────────────────────┐
│ Tauri WebView（UI 包组装） ── 本地 agent（rig-core 调用） ── 本地工具/审批/存储 │
│      │ IPC（命令表 + 事件）                        │ HTTP/WS                     │
└──────┼─────────────────────────────────────────────┼───────────────────────────┘
       │                                             ▼
┌──────┴──────────────── 服务端（企业版）──────────────────────────────────┐
│ axum 单二进制（webadmin/门户/客户端安装包内嵌）                              │
│ auth · users · wallet · gateway · skills · connectors · apps · audit      │
│ cordis 宿主 + PostgreSQL（唯一库） + 进程内队列/缓存（无 Redis/MQ/S3）        │
└───────────────────────────────────────────────────────────────────────────┘
       构建期：editions/*.toml + OEM 渠道目录 → zk compose → 两端 glue + 路由表 + UI registry
```

**关键边界**：agent 循环在客户端；服务端只做认证、用户、钱、网关、内容分发、WASM 执行、审计、管理。
这是"本地能力可用 + 集中管控"的折中（ADR-028）。

## 3. 核心决策（v3 新增标 ★）

| # | 决策 | 理由 | ADR |
| --- | --- | --- | --- |
| 1 | 构建期组合，不做运行时加载 | 内核无 ABI；单二进制；编译期契约校验 | 001 |
| 2 | 契约 crate 是唯一稳定缝，一契约一 major | Rust trait 身份由 crate 实例决定 | 002 |
| 3 | `requires` 只写角色不写包名 | 否则换包即编译失败 | 004 |
| 4 | UI 贡献静态声明，运行期只过滤 | 否则构建期无法做闭包校验 | 017 |
| 5 | 平台壳是契约角色，应用清单由生成器产出 | 换壳只改 profile | 018 |
| 6 | 信任边界是构建输入，不做运行时插件市场 | 同进程静态链接下沙箱是修辞 | 012 |
| ★7 | **企业版 = (个人版 − 个人专属包) + 企业管控包**（继承、排除、追加、覆盖角色） | 个人版先交付；企业版不另造客户端基线 | 020/043 |
| ★8 | 服务端也是 cordis 包 + 构建期组合 | 与客户端同一套模型；OEM 可定制服务端 | 021 |
| ★9 | 每个服务端包自带不可变迁移 + 校验和，只前向修复 | 参考实现的"迁移被改写导致不可恢复"事故 | 022 |
| ★10 | 钱只有一本账（余额），网关结算与 usage 同事务 | 参考实现四套并行额度的技术债 | 023 |
| ★11 | OEM = 私有索引仓 + 每客户 submodule，构建期注入渠道 | 客户隔离、可复现、可审计；品牌不可线上篡改 | 024 |
| ★12 | 交付面自包含：镜像内带客户端安装包、门户、compose | 内网零外网依赖、版本天然配套 | 025 |
| ★13 | WASM 应用：服务端执行 + 客户端独立 origin 开窗 + 每应用 SQLite；不可调 AI | 参考实现已验证形态；缩小能力面 | 026 |
| ★14 | 认证单一主源 + 本地应急超管；JWT+refresh | 避免多源冲突；桌面端需要无 cookie 会话 | 027 |
| ★15 | 服务端弱管控：只管身份/钱/商店/记录 | 需求方定；安全责任在客户端与客户网络 | 030 |
| ★16 | 网关只支持 Responses API | 需求方定；减少协议面 | 031 |
| ★17 | 删除部门/用户组；角色超管/审计员/员工 | 需求方定 | 032 |
| ★18 | 不做 Windows 代码签名 | 无证书预算 | 033 |
| ★19 | 月全额发放、仅管理员充值、峰谷价、流式透支 | 需求方逐条确认 | 034 |
| ★20 | TS/Rust 最严格检查 + 边界运行时校验 + CI 0 容忍 | 防止技术性 bug | 039 |

## 4.5 优先级顺序（客户端优先）

| 顺位 | 做什么 | 为什么先做 |
| --- | --- | --- |
| 1 | 客户端骨架：Tauri + React 壳 + 包组合 + UI registry + IPC + mock agent | 能看见、能演示；所有后续能力都挂在这上面 |
| 2 | **个人版客户端完整闭环**：本地 agent、工具、审批、会话、自配 provider、GitHub Releases 更新、安装包 | 个人版不需要服务端，最快形成可交付产品；它是企业版的基础 |
| 3 | **企业版 = 个人版 + 企业管控包**：登录/JWT、网关 provider、技能/连接器/应用客户端、服务端（认证/钱包/网关/商店/审计）、管理台 | 企业版不另做客户端基线，只在个人版之上叠加管控包并覆盖少数角色 |
| 4 | 商店（技能/连接器）+ 审计 | 客户端侧安装/更新/启用为主，服务端只做分发 |
| 5 | WASM 应用中心（Go 先，Rust 后） | 增值能力，前四步稳定后再做 |
| 6 | OEM/交付/加固 | 最后做渠道化与发布 |

## 6. 与参考实现（ZeoKeel-Harness）的关系

**借鉴**：单进程 + PostgreSQL + 内嵌管理台；路由唯一真源 + 权限点同处申报；技能/应用/Agent 共用
`apps + releases + grants` 内容模型；网关"准入→转发→计量→结算"四段式；限额单一真源 + 生成物；
交付面自包含；渠道/品牌构建期注入。

**不照搬**：Go/Electron 技术栈；多套并行额度；运行时 build tag 裁剪（我们用 profile）；
WASM 应用曾内置 AI 能力（已删除，我们不提供）；Windows 安装包不签名（我们也不签，ADR-033）。

## 7. Top 风险（完整见 `13-risks-and-adr.md`）

| 风险 | 缓解 |
| --- | --- |
| 范围过大（两端 + 7 域 + OEM + 双版本） | 严格按 M1 个人版 → M2 企业版递进；每阶段可交付可演示 |
| 服务端安全（认证/密钥/网关/多租户） | 单租户；密钥不出服务端；安全评审门禁；参考实现的安全审计清单 |
| 网关只支持 Responses 导致兼容性下降 | 上游仍可兼容 OpenAI；客户端只做 Responses；后续按需扩展（ADR-031） |
| 弱管控下员工行为风险 | 服务端不兜底；文档/销售明确边界；安全责任在客户终端与网络（ADR-030） |
| OEM 私有仓与 CI 权限 | deploy key + commit pin；索引仓与客户仓最小权限；产物隔离 |
| 迁移事故 | 不可变迁移 + 内容哈希 + 只前向修复；备份/恢复演练 |
| 计费漏洞 | 结算与 usage 同事务；未定价模型拒绝；预授权 + 兜底 |
| WASM 沙箱逃逸/资源耗尽 | wasmtime + wasip1、每应用限额、无网络/文件、独立 DB、并发配额 |
| Windows 签名缺失（已接受） | 文档/门户提示 SmartScreen + SHA256；所有渠道一致，不做 OEM 签名例外（ADR-033） |
| 个人版与企业版代码分叉 | 同库 edition + CI 同时构建测试 |
