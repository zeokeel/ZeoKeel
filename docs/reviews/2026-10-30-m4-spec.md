## 3. P0（阻塞）

### P0-1 · 员工上传链路缺失，权限与 docs/07/docs/12 冲突

- `proposal.md:9`、`docs/12:143/156`、`docs/07:136` 都要求“员工可上传 WASM 应用，管理员审核/上架”。
- 但 `spec.md:15-18` 只有 **admin** API：`GET/POST /api/admin/apps`、`POST /api/admin/apps/{id}/versions`、`approve|reject|...`；`spec.md:18` 明说“权限：管理写 super_admin+CSRF；员工仅可见/可开”。
- 没有员工 `POST /api/client/v1/apps` 上传、pending 状态、owner/transfer、`apps:publish` 权限；`tasks.md` 也没有“员工上传”任务。
- 结果：M4 退出条件“员工上传 → 管理员审批”无法执行；实现只能管理员代传，违反 docs/07/12。

**修法**：补员工上传 API（multipart wasm + manifest）与 `apps:publish`/`apps:read`/`apps:use`/`apps:admin` 权限矩阵；明确 owner、visibility/grants、转交、非 owner 更新拒绝；tasks 增加“员工上传/审批/转交”任务与 e2e 负向。

### P0-2 · 客户端执行/不执行应用、UI wasm 边界与 docs/04 冲突

- `docs/04:111` 明确：“客户端**不执行应用、不持有应用 DB**”；`docs/04:222-233` 是客户端只发请求信封。
- `spec.md:16` 的 `POST /apps/{id}/open` 返回 `session_id/ui_wasm?`；`spec.md:31` 说“客户端独立窗口（Tauri）或 sandbox iframe 加载隔离页”；`design.md:11` 说 `ui-apps` 目录/打开/错误页。
- “UI wasm”由谁执行没有定义：若客户端在 WebView 执行 UI WASM，就是“客户端执行应用”，与 docs/04 冲突；若服务端执行，客户端又拿不到可渲染 UI。`ui_wasm?` 是可选字段，等于把核心架构留成问号。
- 同时 docs/07 §7 说“应用 UI 编进 wasm”，与 docs/04 §2.6 的“客户端不执行应用”本身也需要 ADR/SSOT 收敛。

**修法**：先定 ADR/更新 docs/04/07：① M4 只做服务端 guest + 静态 UI（HTML/JS/CSS 或静态资源清单），客户端不执行 UI WASM；或 ② 明确客户端 WASM UI 沙箱（独立 host/ABI/权限），并改 docs/04 的“客户端不执行应用”。`open` 返回值必须是确定的 `ui_url/asset_manifest/version`，不能 `ui_wasm?`。

### P0-3 · 客户端独立 origin/窗口隔离不可执行，Tauri 窗口可绕过 `app_request`

- `docs/04:222` 要求：每应用独立 origin `<app_origin_scheme>://<app_id>/<path>`、scheme 由渠道配置且跨渠道唯一、窗口创建前注册 **privileged**、每应用独立 partition、导航闸门只本 origin。
- `design.md:31-32` 只有“Tauri WebviewWindow + 临时目录文件/自定义协议”“iframe sandbox=allow-scripts + srcdoc”，没有 scheme 注册、channel 配置、partition、privileged、导航闸门；`proposal.md:34` 仍把 scheme 作为未决问句。
- `spec.md:31` 只说“窗口无 Node/preload 权限”；Tauri 窗口默认仍可访问 `window.__TAURI__`/IPC。`docs/21:82` 要求 WASM 应用窗口**只允许 `app_request`**，需单独 capability 文件/白名单，spec 未落。
- serve 的 `srcdoc` + `sandbox=allow-scripts` 是 opaque origin（`"null"`），host 必须校验 `event.origin`/`source`/session；spec 未写，存在 postMessage 冒充 host 的风险。

**修法**：在 design 中给 Tauri capability 文件/命令白名单（仅 `app_request`）、channel scheme 唯一性校验/注册、独立 partition、导航闸门、窗口销毁清理；serve 明确 iframe `origin` 校验（opaque origin/session nonce）、CSP、禁止 `allow-same-origin`；补跨 origin 导航/iframe 冒充/窗口残余测试。

### P0-4 · 资源限额契约远少于 docs/04/07，仍可无界消耗

- `spec.md:25`：fuel 10M、墙钟 **5s**、内存 64MB/实例、并发 **4/应用**、DB 100MB/16 表；`design.md:19-20` 只有 per-app semaphore 与 StoreLimits。
- `docs/04:232`/`docs/07`: 请求 **1 MiB**/响应 **8 MiB**；端到端 **60s**、guest **30s**、SQL **5s**；**每应用/每用户/全局**并发限额；超限 **429 + Retry-After**。spec 的 5s 与 guest 30s 直接冲突，且完全没有请求/响应体积、每用户/全局并发、排队上限。
- 上传 wasm ≤32MB 但没有每用户/全局归档/DB 文件/日志总量配额；`app_calls` 30 天、`app_runtime_logs` 1000 行/应用没有全局上限；多用户 × 多 app × 每 app 4 实例 → 无全局内存/CPU/磁盘上界。
- 原型自己承认“没有墙钟/内存上限/并发配额”（`experiments/wasm-poc/README.md:66-68`），M4 spec 没有给出补法/验收细节。

**修法**：按 docs/04/07 冻结统一 limits（request/response、guest 30s/端到端 60s/SQL 5s、per-app/user/global concurrency、queue、429/Retry-After），并加入上传/DB/日志/临时文件的每用户/全局配额与清理策略；在 `zk-kit-wasm` 内实现 epoch + StoreLimits + semaphore + 全局池，acceptance 用并发/耗尽测试证明。

### P0-5 · SQL/DB 隔离只有黑名单，设计允许 DDL，guest 可文件写入/跨表破坏

- `design.md:18` 写“单条 SELECT/INSERT/UPDATE/DELETE/DDL 白名单；拒绝 ATTACH/PRAGMA 危险语句”；**允许 DDL** 与 `docs/04:229`“仅 SELECT/INSERT/UPDATE/DELETE，禁 DDL/ATTACH/PRAGMA”直接冲突。
- 黑名单不能阻止 `VACUUM INTO '/path'`、`load_extension`、`readfile`/`writefile`（若可用）、`CREATE TRIGGER`、`DROP TABLE`、`CREATE VIRTUAL TABLE`、`SELECT ...;` 多语句；spec 没有 SQL parser/单语句 AST 校验，也没有 “SQL 5s” 实现。
- `design.md:18` 的 `sqlite_master` 表数/`fs metadata` DB 大小只是检测，不阻止 guest 在检测前执行 `VACUUM INTO` 或写大文件；`asset.read`（`design.md:16-17`）没有路径/资源清单边界，可能成为文件读取面。
- `app_databases(path, ...)` 有 `path` 列但无“路径必须由服务端生成/校验 app_id”的规则；跨 app DB 隔离只在文字里，没有 host 函数参数约束/测试项。

**修法**：按 docs/04 禁止 DDL；用 sqlparser/AST 做 **单语句** 白名单（只允许 SELECT/INSERT/UPDATE/DELETE，参数绑定），显式拒绝 `ATTACH/PRAGMA/VACUUM/load_extension/readfile/writefile/trigger/virtual table`；`db.*` 不接收 DB 路径/ATTACH 名，只能操作当前 app 的 pinned connection；`asset.read` 只接受 release manifest 内的相对资源名（大小/路径校验），禁止 `..`/绝对/URL；补跨 app DB、`VACUUM INTO`、多语句、注释绕过、`smuggling` 测试。

### P0-6 · C16 spec 门禁当前红；tasks 表不符合 spec-check

- `python3 scripts/spec-check.py` 实测：`tasks.md 缺任务表/验证列`。`tasks.md:3` 表头是 `| # | 任务 | 写作用域 | verify |`，缺 D/F 规范要求的“依赖/验证”列（spec-check 当前解析失败）。
- spec 仍 draft，proposal 无 `- 评审：` 字段；C16 五件套未过门禁前不能开实现。
- `acceptance.md:3` 为 `in-progress`，`tasks.md` 没有 `apps-e2e.sh` 创建任务（`scripts/apps-e2e.sh` 不存在），spec 却把它当首条验收；`tasks.md:10` 用 `scripts/apps-e2e.sh` 但任务 5 才创建，任务 8/9 才补 guest/安全，顺序与验收不一致。

**修法**：按 spec-check 期望修正 tasks 表（补 `依赖`/`验证` 列，或使用仓库模板）；proposal 补 `评审：docs/reviews/2026-10-30-m4-spec.md`；新增独立任务创建 `scripts/apps-e2e.sh` 并定义最小用例；acceptance 的命令/预期/证据目录与任务一一对应。修到 `spec-check` 0 errors 后再评审。

### P1-2 · C3/C4 包/角色/四件套不完整

- `design.md:7` 只写 `packages/contracts/app`；`zk-kit-wasm` 新 kit 没有 `@capability`/能力索引条目（C17）。

### P1-3 · C10 运行时校验缺失

- `spec.md`/`design.md` 没有为 `Frame envelope`、`open` 响应、`request` 请求、wasm manifest、`app_calls` 定义 Rust JSON Schema + 前端 Ajv/TS runtime guard；WASM/帧是外部输入。
- 修：`packages/contracts/app` 生成 `app-frame.json`/`app-open.json`/`app-manifest.json`；客户端 Ajv 校验 host postMessage/API 响应；Rust 端用 serde + schema 校验，禁止 `as`/猜测。

### P1-4 · 应用版本/DB 迁移/退役生命周期未定义

- `spec.md:9` 只有 `app_databases(app_id PK, path, size, quota)`，没有 DB schema version/migration；应用 release 升级（Go guest 新 schema）后旧 DB 如何迁移、失败如何回滚未定义；`design.md:23-27` 应用 release 回滚只回 `contents`，不回 DB。
- `docs/06:99` 有每小时 `app-retire` job（软删→保留期→真删含 DB 文件）；`design.md:27` 说 M4 先手动 `POST /purge`，没有 job/保留期/审计；与 docs/06 冲突。
- 修：定义 per-app DB schema version/migration 协议（guest 自带 migration？host 白名单 DDL？）与失败回滚；退役用 docs/06 job + 保留期配置 + 审计 + 真删测试；明确 rollback 的 DB 兼容策略。

### P1-5 · 客户端隔离与资源边界 testability 不足

- `design.md:31-32` 的 Tauri/iframe 方案未落到 Tauri capability 文件、scheme 注册、partition、origin 校验、CSP；`spec.md:31` “窗口无 Node/preload”不足以满足 docs/21:82 的“只允许 app_request”。
- `tasks.md:10` 的 `scripts/apps-e2e.sh` 尚不存在；任务 9 把 DB/AI/network/memory/fuel/concurrency 安全负向混在一起，没有每项具体命令/断言；`experiments/wasm-poc` 的缺口（timeout/memory/concurrency/SQL gate）没有对应任务的验收命令。
- 修：任务拆细（Tauri capability、origin scheme、iframe postMessage、每个 limit 单测/e2e、跨 app DB、AI/network/file 负向）；补 `scripts/apps-e2e.sh` 创建任务；每项给命令/期望错误码/证据。

### P1-6 · 数据面/asset/SQLite 路径与配额未闭合

- `app_databases.path` 无约束、无每用户/全局配额；`app_runtime_logs` 1000 行/应用没有全局/保留上限；`app_calls` 30 天未定义清理 job；`asset.read` 无资产存储/大小/路径边界。
