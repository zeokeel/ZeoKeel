# 文档评审记录

C19/`docs/11` §9：发现有用方案后先写文档，由非实现者只读评审并记录于此，`APPROVED` 后才写 spec/代码。

文件命名：`YYYY-MM-DD-<topic>.md`，内容至少：范围、评审者、结论（APPROVED / CHANGES-REQUESTED）、
P0/P1/P2 列表（文件:行 + 问题 + 修法）、复评结果、关联 spec。

必填字段（P1 评审要求）：`评审对象`（commit/路径+SHA256）、`评审者`、`与实现者关系/独立性`、`结论`、`P0/P1/P2` 逐条状态、
`复评日期/结论`、`关联 spec`。评审后文档变更导致对象 hash 变化 → 记录失效，需重新评审。
