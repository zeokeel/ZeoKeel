### 2.1 冲突裁决

> 本节只判定各域**内部**的权威文档；全局冲突顺序以 `AGENTS.md` §10 为准（用户 > AGENTS > 00/15 > 19–24 > PLAN > 其它）。

- 组合/manifest/生成物/路由/迁移/关闭/客户端会话 → **`24` 优先**，回写 `02/03/05/06/10`。
- 客户端页面/审批/无障碍/平台集成 → **`19` 优先**，回写 `05/16`。
- 运维/Day-0/备份/升级/SLO → **`20` 优先**，回写 `06/09`。
- 威胁模型/密钥/审计链/隐私 → **`21` 优先**，回写 `04/05/06/07/09`。
- 钱包/配额/计量/价格/对账/报表 → **`22` 优先**，回写 `07` §3。
- OEM 客户流程/支持 → **`23` 优先**，回写 `09` 客户交付段。
- 渠道 schema/更新通道 → **`09` 优先**，`01/23` 只引用。
- 决策结论 → **`15` 优先**；ADR 只写理由与后果；历史文档不作依据。

## 3. 去重规则（强制）

1. **一个规范只写一次**：规则/表结构/流程/验收标准只出现在 SSOT 文档；其它文档写一句"见 X §Y"。
2. **摘要必须标注**：允许 3–5 行摘要，但必须以"摘要，详见 X"结尾，不得包含第二份可执行细节。
3. **数字/清单由生成器产出**：包数、端点数、契约数、限额表不在多处手写。
4. **术语唯一定义**：见 §4；不得在其它文档重新定义。
5. **决策不重复**：`15` 写一句结论；`13` 写理由/后果；其它文档只引用编号。
6. **新增/修改规范时**：先改 SSOT 文档，再全局 `rg` 查找重复，删除/改链接；CI docs-check 检查"同一短语在多文档重复"。
7. **禁止第三人称复述**：不要在不同文档用不同措辞解释同一机制（会造成 AI 语义漂移）。

## 4. 术语表（只在这里定义一次）

| 术语 | 唯一定义 | 定义位置 |
| --- | --- | --- |
| edition | 包集合与产物形态：`personal` / `enterprise` | `01` §1.5、`09` §1 |
| channel | 品牌/身份/默认值（含 server_url）：`official`/`beta`/`oem-*` | `09` §1/§3 |
| profile | 环境覆盖（default/mock/minimal/...），不改变 edition 语义 | `03` §3、`24` §1 |
| OEM 渠道 | 企业版 × 客户 channel；品牌/地址可预置 | `09` §1/§3 |
| 官方企业版 | `enterprise × official`；`server_url` 默认空，客户首配 | `09` §1、`19` §3.3 |
| 余额/配额 | 企业用量配额，非预付资金；不可提现/退款 | `15` D60、`22` §1 |
| 充值/调账 | 管理员分配/调整配额，不涉及金钱收付 | `22` §1 |
| 首配 | `server_url` 为空时首次填写并本地保存 | `19` §3.3 |
| 锁定地址 | 渠道 `server_url` 非空，登录页不显示地址输入 | `09` §3、`19` §3.2 |
| 强制更新 | 服务端标记 `forced`/`min_supported`，低于版本 426 | `09` §7.3 |
| 灰度 | 按渠道/用户比例放量，不是 edition 切换 | `09` §7.3、`04` §3 |
| 包 id | `<vendor>/<name>`，全局唯一 | `02` §1 |
| 角色 | 包在组合中的可替换槽位，如 `tool.fs` | `02` §4、`24` §1.5 |
| 契约 | 包之间的稳定 trait/DTO crate | `02` §5、`04` §1 |
| 生成物 | `@generated` 文件，只能由指定 writer 写 | `24` §3 |
| runbook | 故障处置步骤，不是交付文档 | `20` §7 |
| 交付物 | 镜像/安装包/SBOM/交接包 | `09` §5、`23` §3 |
| 已定清单 | `15` D1–D65 | `15` |
| ADR | 决策理由与后果 | `13` |
| 证据 | 可执行、可复现的测试/日志/报告 | `11` §5 |
| update track | stable/beta 发布轨道，不是 channel | `09` §7.1 |
| 产物 | `dist/<ver>/<channel>/` 内的镜像/安装包/清单 | `09` §4 |
| personal-only 包 | 仅个人版包含的包 id 清单 | `24` §1 |
| kind | 包类型封闭枚举（contract/runtime/...） | `24` §2 |
| facet | 包可同时提供 rust/ui 两个面 | `24` §2 |
| manifest | `zk.toml`，唯一包清单 | `24` §2 |
| upstream/provider | 上游模型供应商；客户端角色叫 `llm.provider.*` | `07` §4 |
| conversation/session | 会话=消息线程；登录会话=JWT/refresh | `24` §7、`04` §3 |
| contents | 商店四表：内容/版本/授权/上架 | `07` §5 |
| hold | 预授权占用，不改余额列 | `22` §4 |

## 6. 维护规则

- 改任何规范：先改 SSOT，再 `rg` 搜索重复段落，删除/链接；PR 必须说明"删除/链接了哪些重复"。
- 新增文档：必须在本文 §2 注册主题，禁止"先写文档再找位置"。
- 术语：新术语先加入 §4，再使用。
- 变更流程：先建 `specs/changes/<id>/` 五件套；`python3 scripts/spec-check.py` 必须通过；完成后归档 `specs/archive/`。
- 门禁：`python3 scripts/docs-check.py` + `python3 scripts/spec-check.py` 都需 0 error。
