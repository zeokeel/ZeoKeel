# QA 审计（红队）：可验收性 / 边界 / 并发 / 安全

> 只读审计，只写本文件。范围：`AGENTS.md`、`docs/00–18`、`PLAN`、`experiments/*/README.md`。
> 判定标准（取自 `docs/11-testing-and-evidence.md:3,52`）：**一条设计若不能写成"输入 → 期望输出 → 失败也红"的可执行断言，就不算完成。**
> 结论：**P0 5 / P1 15 / P2 9**。测试体系"有层级、缺产品矩阵"；失败注入只存在于里程碑口号里；
> 五处门禁可被合法路径洗白（结算、迁移、解压、Host、capability）。

## 4. 对抗性：1 周内最能打穿设计的 5 个问题

1. **无限透支（钱）**：攻击=员工并发 50 条 `stream:true` 请求，每条触发超长输出；准入只看"余额>0"且允许负余额 → 分钟级制造任意欠费。最小修复=准入按 `max_output_tokens` 预扣 hold + 负余额下限 + 每用户并发流上限（`07:123-126,13:418`）。
2. **WASM 应用页直调 IPC（沙箱）**：失败路径=应用页面执行 `window.__TAURI_INTERNALS__.invoke("ipc_call",{name:"tool.shell.run"})`，绕过服务端"无 AI/无网络/无文件"的全部承诺。最小修复=每 app capability 只放 `app.request`，并加"调用其他命令必失败"的 e2e（`04:222,07:207`）。
3. **结算缺口（账）**：攻击=流式开始后客户端 kill 连接/服务端 kill -9/上游中途 5xx；无 usage 行即免费，重试首字节后又可能双计。最小修复=开流写 pending+hold、断线即 finalize、崩溃对账（`07:123-125,04:79`）。
4. **serve 载体 rebinding（本地提权面）**：攻击=恶意页面用自有域名 rebind 到 `127.0.0.1:<port>`，同源读页面拿一次性 token，再驱动 agent 读写文件/执行命令。最小修复=Host/Origin 精确白名单 + token 绑 Host（`05:297-299`）。
5. **技能包"假绿"（供应链）**：攻击=上传 16MB 高压缩比 zip（解压数 GB）+ `../` 条目；服务端不解压故测试永远通过，客户端无规格。最小修复=客户端解压规格 + 用例下移到 T3 + 解压总量上限（`11:36,07:155-157`）。

## 5. 必须补齐的验收/测试（≤10 条，全部可执行）

1. `gateway_billing_hold`：50 并发流 + 客户端断连 + 服务端 `kill -9`，断言账本支出 ≤ Σhold、无 pending 残留、无重复 usage。
2. `app_window_capability`：应用页调用 `ipc_call("tool.shell.run")` 必须失败；断言窗口内 Tauri 注入对象不可用。
3. `serve_rebinding`：`Host: evil.example` 且解析到 127.0.0.1 的请求必须 403；token 跨 Host 不可复用。
4. `skill_archive_safety`：`../../`、symlink、200MB 解压炸弹三种归档必须拒绝；断言执行在 client T3。
5. `migrations_from_tag`：与上一 release tag 比对，任何历史迁移字节变化必红；`zk db lock` 不得改既有条目。
6. `grant_backfill`：停机 3 个月后启动，断言 3 条发放、余额正确；overwrite 与 100 并发扣费无丢失。
7. `refresh_race`：100 并发 refresh 不触发族吊销；禁用用户后 ≤5s 调 `/v1/responses` 必 401。

9. `io_fault_matrix`：磁盘满/PG down/审计插入失败，断言钱与认证 fail-closed、AI 走 pending 不丢账。
10. `limits_single_source`：`limits.json` 与 Rust 常量/文档/UI `--check` 一致；每个边界 ±1 参数化用例。
